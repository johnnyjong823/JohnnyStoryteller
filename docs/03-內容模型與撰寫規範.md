# 03 — 內容模型與撰寫規範

> 這份文件的目標：讓你看完就能說「我可以照著這個交一篇故事給你」。

---

## 一篇故事的檔案結構

```
src/content/stories/xiao-hong-mao/
├─ index.md                 # 整篇故事的全部資料
└─ images/
   ├─ cover.webp            # 封面
   ├─ 01.webp
   ├─ 02.webp
   └─ ...
```

### 命名規則

| 對象 | 規則 | 範例 |
|---|---|---|
| 資料夾名（= slug = 網址） | 小寫英數 + 連字號，用拼音或英文 | `xiao-hong-mao`、`the-brave-turtle` |
| 場景圖 | 兩位數補零 + `.webp` | `01.webp` … `16.webp` |
| 封面 | 固定 `cover.webp` | |

**⚠ 不要用中文當資料夾名。** 網址會變成一長串百分號編碼（`%E5%B0%8F%E7%B4%85...`），難分享、難除錯，某些工具也會出問題。

**⚠ 場景圖一定要補零。** `2.webp` 會排在 `10.webp` 後面，`02.webp` 才會排對。

## `index.md` 完整範例

```yaml
---
title: 小紅帽
summary: 一個女孩要去看生病的奶奶，路上遇到了大野狼。
cover: cover.webp
category: 經典童話
tags: [勇敢, 森林, 家人, 陌生人]
ageRange: [4, 8]
minutes: 6
status: published

scenes:
  - image: "01.webp"
    alt: 穿著紅色斗篷的小女孩站在小屋門口，手裡提著蓋著格子布的籃子
    caption: |
      從前從前，有一個小女孩。
      她總是戴著奶奶送的紅色斗篷，
      所以大家都叫她小紅帽。
    note: 語速放慢。可以問：「你有沒有最喜歡的一件衣服？」

  - image: "02.webp"
    alt: 媽媽蹲下來把籃子交給小紅帽，兩人在廚房裡
    caption: |
      有一天，媽媽對她說：
      「奶奶生病了，你幫我送這籃點心過去好嗎？」
    note: 這裡把「幫忙」的語氣做出來，不是命令。

quiz:
  - type: choice
    question: 小紅帽要去看誰？
    options: [奶奶, 老師, 鄰居的狗]
    answer: 0
    explain: 她要去看生病的奶奶，還帶了一籃點心。

  - type: open
    question: 如果路上有不認識的人跟你說話，你會怎麼做？
    hint: 引導方向：不用害怕，但要先找爸爸媽媽或老師。沒有標準答案，讓他自己說說看。
---
```

## 欄位說明

### 故事層級

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `title` | string | ✓ | 故事名稱 |
| `summary` | string（20–80 字） | ✓ | 選單卡片上顯示，也是**搜尋的主要來源** — 寫的時候想著「三個月後我要用什麼關鍵字找到它」 |
| `cover` | string | ✓ | 封面檔名，相對於 `images/` |
| `category` | enum | ✓ | **單選**，必須在白名單內 |
| `tags` | string[] | ✓ | **3–6 個**，必須在白名單內 |
| `ageRange` | [number, number] | ✓ | 建議年齡，例 `[4, 8]`，用於篩選 |
| `minutes` | number | ✓ | 預估說書時間（分鐘），用於篩選 |
| `status` | `draft` \| `published` | ✓ | `draft` 不會出現在正式站，可以安心先寫一半 |
| `scenes` | Scene[] | ✓ | **8–16 個**（建議 12） |
| `quiz` | Quiz[] | ✓ | **固定 2 題** |

### Scene（每一頁）

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `image` | string | ✓ | 圖檔名 |
| `alt` | string | ✓ | 圖片描述，給無障礙與搜尋用。**寫「畫面上有什麼」，不是重複 caption** |
| `caption` | string | ✓ | 說書人要念的正文。多行用 `\|` |
| `note` | string | ✗ | 給說書人的提示：什麼時候停、問什麼、用什麼語氣 |

**`alt` 與 `caption` 的差別**（常見錯誤）：

```yaml
caption: 從前從前，有一個小女孩。          # 你要念的話
alt: 穿著紅色斗篷的小女孩站在小屋門口     # 畫面上實際有什麼
```

`alt` 寫成 `caption` 的複製貼上，等於沒有 alt。

### Quiz（結尾兩題）

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `type` | `choice` \| `open` | ✓ | |
| `question` | string | ✓ | 題目 |
| `options` | string[] | `choice` 必填 | **2–3 個**。四個以上對學齡前太多 |
| `answer` | number | `choice` 必填 | 正確選項的索引，**從 0 開始** |
| `explain` | string | `choice` 必填 | 答對後顯示的一句話 |
| `hint` | string | `open` 必填 | 給說書人的引導方向（孩子看不到） |

### ★ 建議的兩題組合

> **第 1 題 `choice`** — 檢查有沒有聽懂（回憶型，答案就在故事裡）
> **第 2 題 `open`** — 延伸到他自己的生活（沒有標準答案）

這個組合有意義：第一題讓孩子確認「我有跟上」，第二題把故事變成他自己的事。純選擇題會變成考試，純討論題會讓他覺得沒有完成感。

**不計分、不排名、不記錄。** 原因見 [05](./05-畫面與互動設計.md#為什麼不計分)。

## 分類與標籤白名單

### 問題

你自己說了「故事很雜」。如果標籤可以自由填，三個月後你會有：

> 勇敢 / 勇氣 / 有勇氣 / 不怕 / 很勇敢

五個意思一樣的標籤。篩「勇敢」只篩到五分之一的故事 → **篩選功能等於廢掉**。

而這件事**不能靠自律解決** — 你在寫第 87 篇故事的時候不會記得第 12 篇用的是哪個詞。

### 解法：白名單 + 建置時驗證

```ts
// src/content/taxonomy.ts

/** 分類：單選。上限 12 個 —— 想加第 13 個之前，先想能不能歸進現有的 */
export const CATEGORIES = [
  '經典童話',
  '品格養成',
  '生活習慣',
  '情緒認識',
  '自然與動物',
  '科學探索',
  '節慶與文化',
  '家庭與朋友',
  '安全教育',
] as const;

/** 標籤：多選，每篇 3–6 個。可以慢慢長，但每次新增都要是有意識的動作 */
export const TAGS = [
  // 情緒
  '勇敢', '害怕', '生氣', '難過', '開心', '嫉妒', '緊張',
  // 關係
  '家人', '朋友', '分享', '道歉', '合作', '陌生人',
  // 場景
  '森林', '海洋', '學校', '夜晚', '下雨', '城市', '農場',
  // 品格 / 主題
  '誠實', '耐心', '努力', '好奇', '負責任', '同理心',
] as const;
```

### 守門員：`src/content.config.ts`

**實際程式碼在 `src/content.config.ts`** —— 為了避免文件與程式碼各說各話，這裡只列它實際擋下哪些東西：

| 規則 | 錯了會怎樣 |
|---|---|
| `category` 必須在 `CATEGORIES` 白名單 | build 失敗，並**列出全部 9 個合法分類** |
| `tags` 必須在 `TAGS` 白名單，且 3–6 個 | build 失敗，並**列出全部合法標籤** |
| `summary` 20–80 字 | build 失敗 |
| `scenes` 8–16 個 | build 失敗 |
| `image` 必須是 `01.webp` 這種兩位數補零格式 | build 失敗 |
| **`image` 必須從 01 連續編號** | 「第 3 個場景的 image 應該是 `03.webp`，實際是 `3.webp`」 |
| `alt` 至少 8 字 | build 失敗 |
| `quiz` **剛好 2 題**，第 1 題 `choice`、第 2 題 `open` | build 失敗 |
| **`answer` 是 0-based 且不能超出 `options` 範圍** | 「answer 是 5，但只有 3 個選項。注意 answer 從 0 開始」 |
| `ageRange` 最小值不能大於最大值 | build 失敗 |

最後兩條紅字是**專門為 LLM 設的**——「answer 寫成 1-based」和「檔名沒補零」是 Manus 最常犯的兩個錯。

> ⚠ Astro 5 的 schema 檔案在 **`src/content.config.ts`**（專案根的 `src/` 底下），不是舊版的 `src/content/config.ts`。內容用 `glob` loader 載入，資料夾名就是 slug。

### ★ 核心觀念

> **讓錯誤在 build 時就爆炸，而不是在你說故事給孩子聽的時候才發現。**

打錯一個標籤 → `npm run build` 失敗，訊息直接告訴你哪一篇、哪一行、正確的選項有哪些。這比任何規範文件都有效。

## 新增一篇故事的 SOP

```
① 你：想清楚「我要跟孩子說什麼」
   不是「幫我寫一個關於勇敢的故事」
   而是「我想講：害怕是正常的，重要的是害怕時還是去做。他最近不敢自己睡」

② Manus：貼上 08 的提示詞範本 → 拿到一份 JSON
   （分場腳本 + 角色設定表 + 12 個繪圖提示詞 + quiz，一次到位）

③ 你：npm run import-story -- ./manus-output.json
   自動產生 index.md + prompts.md，並立刻驗證
   有錯會直接告訴你哪一欄、為什麼、合法選項是什麼

④ 你：改 note   ★ 不要跳過，這是這個網站的靈魂
   AI 產的 note 很空泛，你的 note 才是你和孩子之間的東西

   ┌ 想先看到效果？（推薦，尤其是前幾篇）─────────────┐
   │ npm run placeholders -- <slug>                    │
   │ npm run prepare-images -- <slug>                  │
   │ npm run dev                                       │
   │ → 用色塊佔位圖先跑完整流程，確認節奏對不對         │
   │   再花時間去產真正的圖                             │
   └───────────────────────────────────────────────────┘

⑤ 你：用 prompts.md 的角色設定表產第 1 張參考圖，確認角色長相
   不滿意就重產這一張 —— 不要帶著不滿意的角色往下走

⑥ 你：用參考圖 + 12 個場景提示詞產圖，再加一張封面
   詳見 04-圖片製作指南

⑦ 你：圖丟進 src/content/stories/<slug>/images/（png/jpg/webp 都可以）
   npm run prepare-images -- <slug>
   會自動壓成 1600px WebP master + 產響應式變體
   非 webp 的原檔會被移到 <slug>/raw/（不進版控）

⑧ 你：把 index.md 的 status 從 draft 改成 published

⑨ 你：npm run dev，在手機上開來看一遍

⑩ git push → GitHub Actions 自動部署
```

> ⚠ npm 傳參數要用 `--` 分隔，少了它參數不會傳進腳本。

**完整範本、七個陷阱與匯入腳本規格見 [08-用-Manus-產生故事](./08-用-Manus-產生故事.md)。**

兩個不能省的人工步驟：

- **步驟 ④（改 note）** — 這是這個網站跟一般故事 App 的唯一差別
- **步驟 ⑤（確認角色長相）** — 角色不對，後面 12 張圖全部要重來，值得多花時間

其餘都可以自動化。

> ⚠ 因為故事由 LLM 產生，[上面的白名單](#分類與標籤白名單)**必須整份貼進 Manus 的提示詞**。Manus 不知道你的 `taxonomy.ts`，不貼的話它一定會自己造標籤，然後 build 失敗。

## 內容撰寫的實務建議

### caption（要念的正文）

- **一頁 2–4 行**。超過就該拆成兩頁 — 孩子的注意力跟不上長段落
- **用口語，不要用書面語**。你是要念出來的，不是給人讀的
- 用 `|` 保留換行，換行的地方就是你要停頓的地方
- 不要在 caption 裡寫「（停頓）」這類指示 — 那是 `note` 的工作

### note（給說書人的提示）

真正有用的 note 長這樣：

```yaml
note: 語速放慢。可以問：「你有沒有最喜歡的一件衣服？」
note: 這裡把「幫忙」的語氣做出來，不是命令。
note: 這一頁停久一點，讓他看清楚狼躲在哪裡。
note: 如果他開始緊張，可以先說「不要怕，等一下會沒事」。
```

沒用的 note：`繼續念下一頁`、`這裡很重要`。

### 分場的節奏

12 場的典型結構：

| 場次 | 作用 |
|---|---|
| 1–2 | 介紹角色與日常 |
| 3–4 | 事情發生了 |
| 5–8 | 遇到困難、嘗試、失敗 |
| 9–10 | 轉折 |
| 11–12 | 解決 + 收尾 |

不用死守，但如果某一段佔了 8 頁，通常是該拆成兩篇故事了。

## 開放問題

- **系列故事**：同一組角色的多篇故事，目前 schema 沒有 `series` 欄位。需要時加一個字串欄位即可，成本很低 — 先不做。
- **標籤上限**：目前設 3–6 個。實際用一陣子後可能會想放寬到 8 個，改 schema 一行的事。
