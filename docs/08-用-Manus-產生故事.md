# 08 — 用 Manus 產生故事

> 你的計畫：用 [Manus](https://manus.im) 產生故事結構，直接餵 [03 的 schema](./03-內容模型與撰寫規範.md)。
> **方向完全正確** — schema 就是契約，把契約交給 AI 是對的做法。但有七個陷阱一定會踩到，這份文件是為了讓你一次跳過。

---

## 核心建議：要 JSON，不要 YAML

**這是這份文件最重要的一句話。**

`index.md` 的 frontmatter 是 YAML，但**不要叫 Manus 直接輸出 YAML**。原因：

| YAML 的問題 | 後果 |
|---|---|
| 縮排敏感 | 差一個空格整份解析失敗 |
| `caption: \|` 多行字串 | LLM 最容易寫壞的結構，中文標點更容易出錯 |
| 中文冒號 `：` 與半形 `:` 混用 | 解析成錯誤的 key |
| 字串要不要加引號的規則很微妙 | `4-8` 可能被解析成字串、也可能出錯 |

**JSON 沒有這些問題** — 沒有縮排語意、沒有區塊字串、引號規則單純，而且 LLM 產 JSON 的可靠度遠高於 YAML。

```
Manus 產出 JSON  →  npm run import-story  →  自動生成 index.md（YAML frontmatter）+ prompts.md
```

轉換由腳本做，機器做機器擅長的事。

## 七個一定會踩到的陷阱

| # | 陷阱 | 為什麼會發生 | 解法 |
|---|---|---|---|
| 1 | **發明新標籤** | Manus 不知道你的白名單，會自己造「勇氣」「有勇氣」 | **把 `taxonomy.ts` 的白名單整份貼進提示詞**，並要求「只能用這些字串，一個字都不能改」 |
| 2 | **`alt` 變成 `caption` 的複製** | LLM 天生偷懶，看到兩個文字欄位就複製 | 在提示詞裡放**對照範例**，明說 alt 是「畫面上有什麼」、caption 是「你要念的話」 |
| 3 | **`answer` 寫成 1-based** | 人類直覺是從 1 開始 | 明寫「**索引從 0 開始**，第一個選項是 0」，並在範例中示範 |
| 4 | **quiz 數量不對** | 沒說死就會給 3 題、5 題 | 明寫「**剛好 2 題，第 1 題 `choice`、第 2 題 `open`**」 |
| 5 | **簡體中文／中國用語** | 訓練資料以簡中為大宗 | 明寫「**繁體中文、台灣用語**」，並舉例：用「影片」不用「視頻」、用「品質」不用「質量」 |
| 6 | **`summary` 太長或太短** | 沒給範圍就隨便寫 | 明寫 **20–80 字**，並說明它是搜尋的主要來源 |
| 7 | **`note` 寫得很空泛** | AI 不知道你的說書風格 | 見下方「不要外包給 AI 的部分」 |

## ⚠ 不要外包給 AI 的部分

Manus 可以做很多，但有兩樣東西**你自己來會好很多**：

### 1. 故事的核心（你想跟孩子說什麼）

不要對 Manus 說「幫我寫一個關於勇敢的故事」。要說：

> 「我想跟我的孩子講：**害怕是正常的，重要的是害怕的時候還是去做**。他最近不敢自己睡。」

前者你會拿到一篇通用的網路故事；後者你會拿到一篇為你的孩子寫的。

### 2. `note`（說書人提示）

AI 產的 note 長這樣：

```
❌ note: 這裡語氣要溫柔
❌ note: 強調主角的勇氣
```

好的 note 長這樣：

```
✅ note: 這裡停一下，讓他看清楚狼躲在哪裡。
✅ note: 如果他開始緊張，先說「不要怕，等一下會沒事」。
✅ note: 這句用你平常叫他起床的語氣念。
```

差別在於 note 是**你和你的孩子之間的東西**。讓 Manus 產一版當骨架，但**每一篇都自己改過一遍** — 這一步花不了五分鐘，卻是這個網站跟一般故事 App 的唯一差別。

## ★ 產生提示詞：一行指令

**不要手動複製下面的範本** —— 白名單會跟 `taxonomy.ts` 脫節，那是 LLM 產內容最主要的失敗原因。

```bash
npm run manus-prompt -- "我想跟孩子講：東西玩完要自己收好。他最近玩具丟得滿地都是。"
```

產出 `manus-prompt.txt`，**白名單直接讀自 `src/content/taxonomy.ts`，永遠不會過期**。整份貼進 Manus 就好。

不帶參數也可以（之後自己編輯檔案裡的「我想說的故事」那段）：

```bash
npm run manus-prompt
```

## 提示詞範本（給你理解內容用）

以下是 `manus-prompt.txt` 的內容長相。**實際使用請跑上面的指令**，不要從這裡複製 —— 這份文件裡的白名單只是示意，不保證跟程式碼同步。

````text
你是兒童繪本的分場編劇。請把我的故事構想，轉成一份結構化的 JSON。

## 讀者設定
- 聽故事的孩子：{ 年齡，例如 5 歲 }
- 說故事的人：孩子的爸爸（會照著 caption 念出來）
- 語言：**繁體中文、台灣用語**。禁止簡體字與中國用語
  （用「影片」不用「視頻」、用「品質」不用「質量」、用「馬鈴薯」不用「土豆」）

## 我想說的故事
{ 這裡寫你的構想。越具體越好，例如：
  我想跟孩子講「害怕是正常的，重要的是害怕的時候還是去做」。
  他最近不敢自己睡覺，一定要開燈。
  希望故事裡有一隻小動物，最後靠自己克服。 }

## 輸出格式
**只輸出一個 JSON 物件，不要有任何說明文字、不要包在 markdown 程式碼區塊裡。**

```
{
  "slug": "英文或拼音的小寫短名，用連字號，例如 brave-little-owl",
  "title": "故事名稱（繁體中文）",
  "summary": "20-80 字的摘要",
  "category": "從下方分類白名單選 1 個",
  "tags": ["從下方標籤白名單選 3-6 個"],
  "ageRange": [最小年齡, 最大年齡],
  "minutes": 預估說故事的分鐘數（整數）,

  "characterSheet": {
    "name": "主角名字",
    "description": "英文的角色外觀描述，要非常具體：年齡、臉型、眼睛顏色與大小、髮型髮色、每一件衣服的顏色與款式、鞋子。這段會被原封不動貼進每一張圖的繪圖提示詞裡"
  },
  "styleToken": "英文的畫風描述，整篇故事共用。必須包含 no text, no letters, no watermark",

  "scenes": [
    {
      "image": "01.webp",
      "alt": "繁體中文。描述【畫面上實際有什麼】，給視障讀者與搜尋用",
      "caption": "繁體中文。說書人要【念出來】的話。2-4 行，換行處就是停頓處",
      "note": "繁體中文。給說書人的提示：什麼時候停、問什麼、用什麼語氣。可省略",
      "imagePrompt": "英文。完整的繪圖提示詞，格式見下方規則"
    }
  ],

  "quiz": [
    {
      "type": "choice",
      "question": "繁體中文題目",
      "options": ["選項A", "選項B", "選項C"],
      "answer": 0,
      "explain": "答對後顯示的一句話"
    },
    {
      "type": "open",
      "question": "繁體中文的開放討論題",
      "hint": "給說書人的引導方向"
    }
  ]
}
```

## 規則（每一條都要遵守）

### 分類白名單 — 只能用這 9 個，一個字都不能改
經典童話 / 品格養成 / 生活習慣 / 情緒認識 / 自然與動物 / 科學探索 / 節慶與文化 / 家庭與朋友 / 安全教育

### 標籤白名單 — 只能從這裡選，不可以自己造新的
勇敢, 害怕, 生氣, 難過, 開心, 嫉妒, 緊張,
家人, 朋友, 分享, 道歉, 合作, 陌生人,
森林, 海洋, 學校, 夜晚, 下雨, 城市, 農場,
誠實, 耐心, 努力, 好奇, 負責任, 同理心

### 場景
- **12 個場景**（最少 8、最多 16）
- `image` 依序是 "01.webp"、"02.webp" … **兩位數補零**
- 節奏：1-2 介紹角色與日常 / 3-4 事情發生 / 5-8 遇到困難與嘗試 / 9-10 轉折 / 11-12 解決收尾

### caption 與 alt 的差別（最容易寫錯的地方）
**絕對不可以把 alt 寫成 caption 的複製。** 對照範例：

- `caption`: "從前從前，有一個小女孩。她總是戴著奶奶送的紅色斗篷。"
  （← 你要念出來的話）
- `alt`: "穿著紅色斗篷的小女孩站在石頭小屋門口，手裡提著蓋著格子布的籃子"
  （← 畫面上實際有什麼）

### quiz
- **剛好 2 題**。第 1 題必須是 `choice`，第 2 題必須是 `open`
- `choice` 給 **2-3 個**選項，答案就在故事裡（回憶型）
- **`answer` 的索引從 0 開始** — 第一個選項是 0，第二個是 1，第三個是 2
- `open` 沒有標準答案，要把故事延伸到孩子自己的生活

### imagePrompt 的格式
每一個 imagePrompt 都要是這個結構，把 characterSheet.description 和 styleToken 完整貼進去：

```
{characterSheet.description 的完整內容},
{這一頁在做什麼}, {在哪裡}, {手上拿著什麼},
{表情與肢體動作}, {光線},
main subject centered, all important elements within the central square area,
generous empty margins on the left and right sides,
{styleToken 的完整內容}
```

要求：
- **不可以把角色描述簡寫成 "the girl" 或 "she"** —— 每一張都要完整重複，否則 12 張圖會變成 12 個不同的人
- 情緒要明講（例：eyes wide with curiosity / shoulders slumped, looking down）
- 夜晚場景要有明確光源（例：moonlight from the upper left / warm lantern glow）
- 畫面裡不可以有文字

## 輸出前自我檢查
- [ ] category 在白名單內
- [ ] 每個 tag 都在白名單內，共 3-6 個
- [ ] summary 是 20-80 字
- [ ] 場景數 8-16，image 檔名補零且連續
- [ ] 每個 alt 都不是 caption 的複製
- [ ] quiz 剛好 2 題，第 1 題 choice、第 2 題 open
- [ ] answer 是 0-based，且小於 options 的數量
- [ ] 每個 imagePrompt 都完整包含角色描述與 styleToken
- [ ] 全部是繁體中文、台灣用語
- [ ] 輸出是純 JSON，沒有其他文字
````

## 拿到 JSON 之後

### 匯入腳本（實作階段會做）

```bash
npm run import-story ./manus-output.json
```

它會做三件事：

```
manus-output.json
   ├─► src/content/stories/<slug>/index.md      # YAML frontmatter（去掉 imagePrompt 等欄位）
   ├─► src/content/stories/<slug>/prompts.md    # 角色設定表 + 12 個場景提示詞
   └─► 立刻用 zod schema 驗證，有錯就印出哪一欄、為什麼
```

**`prompts.md` 就是你拿去產圖用的檔案** — 它跟故事放在同一個資料夾，之後想重畫某一張，提示詞就在旁邊。

### 為什麼 `imagePrompt` 不放進 frontmatter

繪圖提示詞是**生產過程的記錄**，不是網站要用的資料。放進 frontmatter 會讓內容檔變得又長又難讀。分成兩個檔案，各司其職。

## 完整流程

```
① 你：想清楚「我要跟孩子說什麼」
        │
        ▼
② Manus：貼上面的提示詞 → 拿到 JSON
        │
        ▼
③ 你：npm run import-story  → 自動產生 index.md + prompts.md
        │                       （schema 驗證同時完成，有錯馬上知道）
        ▼
④ 你：改 note   ★ 這一步不要跳過，這是這個網站的靈魂
        │
        ▼
⑤ 你：用 prompts.md 的角色設定表產第 1 張參考圖，確認角色長相
        │
        ▼
⑥ 你：用參考圖 + 12 個場景提示詞產圖
        │
        ▼
⑦ 你：npm run prepare-images <slug>  → 壓成 1600px WebP
        │
        ▼
⑧ 你：npm run dev 在手機上看一遍 → git push
```

**步驟 ④ 和 ⑤ 是唯二不能省的人工步驟。** 其他都可以自動化。

## 常見狀況與修法

| 狀況 | 修法 |
|---|---|
| Manus 輸出被包在 ` ```json ` 區塊裡 | 匯入腳本自動剝掉即可，不用回頭重產 |
| 標籤不在白名單 | 匯入時 zod 會擋下並列出合法選項。回 Manus 說「XX 不在白名單，請改用 YY」 |
| 12 張 imagePrompt 的角色描述被簡寫了 | 回 Manus：「每一個 imagePrompt 都要完整重複 characterSheet.description，不可以用代名詞」 |
| 故事太說教 | 回 Manus：「不要在結尾說出道理，讓故事本身講。把最後兩頁的說教句刪掉」 |
| caption 太長，一頁塞太多字 | 回 Manus：「每個 caption 最多 4 行、每行最多 20 字，超過就拆成兩個場景」 |
| 想要同一組角色的續集 | 把上一篇的 `characterSheet` 與 `styleToken` 貼進新的提示詞，要求沿用 |

## 一個提醒

第一篇故事**先完整跑完整個流程再產第二篇**。你幾乎一定會想調整 schema（例如發現想多一個欄位、或發現 12 頁太多）。

**3 篇時改 schema 很便宜，20 篇時很貴。**
