# 01 — 產品需求

## 這是什麼

一個給說書人用的兒童故事網站。把想說的故事變成一頁一頁的畫面（大圖 + 小字），在平板或手機上說給孩子聽，說完接 2 題小題目。

不是給孩子自己操作的 app，是**給說書人使用的工具**，孩子是觀眾。

---

## ★ 兩種使用者，同一塊螢幕

這是整份設計最重要的一句話。所有 UI 決策都從這裡推導出來。

| | 說書人（大人） | 聽故事的孩子 |
|---|---|---|
| 在做什麼 | 拿著平板、念故事、控制節奏 | 看螢幕、聽故事 |
| 眼睛距離 | 約 30–50 cm | 約 30–60 cm |
| 需要看到 | **文字**：要念的正文 + 什麼時候停、問什麼 | **圖片**：大、清楚、有情緒 |
| 識字能力 | 有 | 可能還沒有 |
| 注意力 | 在故事節奏上 | 在畫面上，很容易被介面干擾 |

因為只有一塊螢幕，兩個人要同時滿足。推導出五條設計原則：

1. **圖片佔絕大部分畫面** — 孩子的視線焦點必須是圖，不是介面
2. **文字小但清楚** — 是「小到不搶戲」，不是「小到看不清」。對比度與字重要夠
3. **文字必須能一鍵完全隱藏** — 有些段落說書人已經記熟了，或想讓孩子純粹看圖
4. **單手可操作** — 另一隻手可能在抱小孩、拿飲料、指著圖說話
5. **不能有孩子誤觸就會毀掉的東西** — 尤其是「回到首頁」

## 使用情境

| 情境 | 對設計的影響 |
|---|---|
| **睡前，房間光線暗** | 深色介面、避免大面積純白刺眼；避免閃爍動畫 |
| **車上、外出，網路不穩或沒網路** | 需要離線能力（PWA 離線收藏） |
| **隨時被打斷**（「等一下我要喝水」） | 進度要保留，回來能接上原本那一頁 |
| **孩子會搶平板** | 關閉鍵要防誤觸；翻頁可以隨便按，但不能跳出故事 |
| **孩子說「再看一次」** | 結束畫面要有明顯的「再看一次」 |
| **臨時要找一篇特定的故事** | 選單要能快速搜尋與篩選（300 篇時尤其重要） |

---

## 功能範圍

### MVP — 第一版必須有

- **故事選單**：封面卡片格狀排列，點擊進入
- **故事播放器**：翻頁、圖大字小、說書人提示、一鍵隱藏文字、字級調整
- **問答**：每篇故事結尾固定 2 題小題目
- **響應式**：手機直向與平板橫向都好用
- **進度保留**：被打斷後回來能接上

### 第二階段 — 內容變多之後

- **搜尋**：標題、摘要、標籤
- **分類篩選**：分類 chips
- **年齡 / 長度篩選**
- **「看過了」標記**
- 篩選狀態同步到網址（可加書籤、可分享）

### 第三階段 — 實際使用之後

- **PWA 離線收藏**：指定故事下載到裝置
- **加入主畫面**：iPhone 上唯一能去掉瀏覽器介面的方法
- **螢幕常亮**：說故事說到一半螢幕不會變暗

## 明確的非目標

寫下來是為了避免以後動搖。這些都**不做**：

| 不做 | 為什麼 |
|---|---|
| **語音朗讀** | 你明確說過不需要 — 說故事的人是你，不是機器。這也是這個產品的核心價值 |
| **使用者帳號 / 登入** | 沒有多裝置同步需求，帳號只會帶來麻煩與個資責任 |
| **內容管理後台（CMS）** | 故事用 Markdown 寫、用 Git 管。做後台的成本遠大於收益 |
| **多人同步 / 即時互動** | 說故事是同一個空間裡的事，不需要連線 |
| **分數 / 排行榜 / 學習歷程** | 對學齡前兒童，答錯的挫折感遠大於答對的成就感；記錄學習歷程還會牽涉兒童個資 |
| **留言 / 社群功能** | 公開網站上的兒童內容加留言 = 需要審核機制。不值得 |
| **後端 API / 資料庫** | 純靜態才能免費、快速、幾乎不會壞 |

## 成功的定義

用這三條來判斷做得對不對：

1. **你想說故事時，10 秒內找到那一篇並開始說。**
   累積到 300 篇時，這個數字仍然是 10 秒 — 這是搜尋與分類存在的唯一理由。

2. **孩子的注意力在圖上，不是在介面上。**
   如果孩子開始想按按鈕、問「那個是什麼」，代表介面太吵了。

3. **你不需要「學」怎麼用它。**
   隔三個月沒用，打開來還是知道怎麼操作。

## 開放問題

這些不擋進度，但需要在對應階段前決定：

- ~~repo 公開還是私有？~~ → **✅ 已決定公開**。連帶產生一條內容紀律：故事裡不放真實姓名與可辨識地點，見 [06-風險評估](./06-風險評估.md#風險-3公開-repo-的內容隱私已決定接受)
- **故事需不需要「系列」概念？**（例如同一組角色的多篇故事）目前 schema 沒有這個欄位。如果之後需要，加一個 `series` 欄位即可，成本很低 — 但先不做。
- **需不需要「隨機一篇」按鈕？** 孩子說「隨便」的時候很好用。列為 MVP 之後的小功能。
