# 05 — 畫面與互動設計

## 設計原則（從 [01](./01-產品需求.md#-兩種使用者同一塊螢幕) 推導）

1. **圖最大，字最小但清楚** — 孩子的視線焦點是圖
2. **單手可操作** — 另一隻手在抱小孩
3. **深色底** — 睡前用，避免大面積純白
4. **沒有孩子誤觸就會毀掉的東西** — 尤其是離開故事
5. **零學習成本** — 隔三個月沒用還是會操作

### 要點

| 項目 | 做法 |
|---|---|
| 卡片 | 以封面圖為主，標題在下方。**點擊區域 = 整張卡片**，不是只有標題 |
| 欄數 | 手機 2 欄、平板橫向 4 欄、平板直向 3 欄 |
| 搜尋 | **即時篩選**（打字就篩），不需要按 Enter |
| 篩選狀態 | **同步到網址** `?q=兔&cat=經典童話&age=4-8` → 可加書籤、可分享 |
| 「✓看過」 | 存 localStorage，卡片右下角小標記 |
| 空結果 | 「找不到符合的故事」+ 一鍵清除篩選 |

### ★ 300 篇時的效能處理

這是選單唯一的技術難點。三個措施：

1. **封面用 320px 縮圖**（約 15 KB），不是原圖
2. **`loading="lazy"`** — 沒捲到的圖不下載
3. **分批渲染** — 一次渲染 60 張，捲到底再載更多

沒做這三件事，300 篇的選單在手機上會直接卡死（300 張原圖 = 幾十 MB）。

## 操作方式

| 動作 | 行為 |
|---|---|
| **向左滑** | 下一頁 |
| **向右滑** | 上一頁 |
| **點畫面右 1/3** | 下一頁 |
| **點畫面左 1/3** | 上一頁 |
| **點畫面中間 1/3** | 收合／展開底部列（設定與頁碼向下滑出，圖片補上空間） |
| 點 `👁` | 切換純看圖模式（文字完全隱藏） |
| 點 `Aa` | 文字大小三段循環（小 / 中 / 大），存 localStorage |
| 點 `✕` | 回選單 — **需要長按 0.5 秒或二次確認**（防孩子誤觸） |
| 鍵盤 `←` `→` `空白` | 翻頁（次要支援，不是主要情境） |

### 必要的細節

| 細節 | 為什麼 |
|---|---|
| **預載入下 2 張、上 1 張** | 翻頁不能有白屏 — 白屏會打斷說故事的節奏，孩子的注意力立刻跑掉 |
| **網址帶頁碼** `/stories/xiao-hong-mao/#3` | 被打斷後重新打開會回到原本那一頁 |
| **進度存 localStorage** | 下次開同一篇會問「要從第 3 頁繼續嗎？」 |
| **翻頁動畫 150–200ms 淡入淡出** | 太慢會拖累節奏；太快會讓孩子沒察覺換頁了 |
| **左右邊緣各留 20px 不偵測手勢** | 避免觸發 iOS Safari 的「上一頁」邊緣手勢 |
| **最後一頁再往下翻 → 進入問答** | 不需要額外按鈕 |

### 結束畫面

```
┌────────────────────────────────────────┐
│                                        │
│           故事說完了 🌙                │
│                                        │
│  ┌──────────────────────────────────┐  │
│  │ [封面]  太陽系・下一篇           │  │  ← 推薦卡（最多 2 張）
│  │         金星：雲朵裡的早安與晚安 │  │
│  └──────────────────────────────────┘  │
│                                        │
│   [  再看一次  ]   [  回故事列表  ]    │
│                                        │
└────────────────────────────────────────┘
```

「再看一次」放在左邊、比較顯眼 — 因為孩子最常說的就是這句。

**推薦卡**：孩子聽完最常說的第二句是「再一篇」，把下一篇直接端到面前。
建置時算好（沒有 JS 邏輯），優先序：

1. **同系列的下一篇** — `series.order` 比自己大的最小那篇（標「◯◯・下一篇」）
2. **故事裡提到的** — `related` 欄位。指向還不存在或還是 draft 的故事時**不顯示**，
   所以可以放心預留（例：水星篇預留赫耳墨斯）
3. 前兩者都沒有時 — **同分類隨便一篇**（用 slug 雜湊挑，同一篇故事每次 build 推薦一樣）

最多 2 張，不做清單 — 結束畫面是給孩子看的，選項多了就變成選單。

### 為什麼不計分

三個理由，都是實質的：

1. **對學齡前兒童，答錯的挫折感遠大於答對的成就感。** 問答的目的是延伸對話，不是評量。
2. **記錄學習歷程會牽涉兒童個資**（COPPA / GDPR-K）。網站一旦公開，這就是真實的法律風險，不是假想的。
3. **孩子會為了拿分數而猜。** 沒有分數，他才會真的想。

所有互動資料（看過的故事、閱讀進度、字級偏好）**只存在裝置的 localStorage，不上傳任何地方**。

## 視覺風格

| 元素 | 建議 | 為什麼 |
|---|---|---|
| 背景 | `#12121a` 這類深色，**不用純黑** | 純黑跟圖片邊緣的對比太硬，會有割裂感 |
| 圖片周圍留白 | 深色（可取圖片主色調暗化） | 亮色會搶走圖片的注意力 |
| caption 文字 | `#e8e6e3` 暖白，**不用純白** | 睡前純白太刺眼 |
| note 提示 | 暖黃 `#f0c674` 之類 | 跟正文一眼分得出來 |
| 正確回饋 | 綠 + **✓ 符號** | 不能只靠顏色（色覺障礙） |
| 錯誤回饋 | 灰化 + 「再想想看」 | 不用紅色 — 紅色對孩子太有攻擊性 |

字級階梯（caption，三段可調）。實際大小 = **基準 × 倍率**：基準隨螢幕大小走，倍率是底部列「Aa」切換的三段。

基準（`--caption-base`，定義在 `global.css`）：

| 螢幕 | 基準 |
|---|---|
| 平板（寬 ≥ 640px） | **22px** |
| 手機直向 | **19px** |
| 矮的手機直向（高 ≤ 700px，如 iPhone SE） | 17px |
| 手機橫向（高 ≤ 520px） | 17px |
| 最窄的手機（寬 ≤ 340px） | 16px |

倍率（`--caption-scale`，存 localStorage）：

| 段 | 倍率 | 手機 | 平板 |
|---|---|---|---|
| 小 | 0.8× | 15px | 18px |
| 中（預設） | 1× | **19px** | **22px** |
| 大 | 1.25× | 24px | 27.5px |

說書人提示（note）固定是 caption 的 **0.9 倍**，不要用「減幾 px」—— 字放大之後差 2px 看起來就一樣大了。

⚠ 實作上 JS 只能改**倍率**（`--caption-scale`），不能直接設 `--caption-size`：行內樣式會整條蓋掉 `calc()`，平板的斷點就失效了。

⚠ 文字面板的 `max-height` 要**乘上同一個倍率**。說書人把字調大，等於在說「現在文字比較重要」，上限沒跟著放寬的話，字放大反而被切掉。改完一定要實際量過每一頁（`scrollHeight - clientHeight`），不能只看第 1 頁的截圖。

「小字」是**小到不搶戲**，不是小到看不清。這一版把預設從 15px 提高到 19px（平板 22px），因為實際用起來太小 —— 說書人在昏暗房間裡要湊很近才看得到。對比度必須符合 WCAG AA（4.5:1）。

## 無障礙與兒童友善

- 所有圖片有 `alt`（[schema 強制必填](./03-內容模型與撰寫規範.md#scene每一頁)）
- 觸控目標至少 **44×44 px**；問答按鈕至少 **64 px 高**
- 對比度符合 **WCAG AA**
- **不用純紅／純綠傳達正誤** → 一律搭配 ✓ 或文字
- 動畫尊重 `prefers-reduced-motion`
- **不要有閃爍效果**（光敏性癲癇風險）
- 鍵盤可完整操作（雖然不是主要情境，但成本很低）

## ⚠ iOS 踩雷清單

因為主力裝置是平板與手機，這一節是實作時最會卡住的地方。

| 問題 | 解法 |
|---|---|
| Safari 網址列會伸縮，`100vh` 會跳動 | 用 **`100dvh`** |
| 下拉會觸發整頁刷新 | `overscroll-behavior: none` |
| 長按圖片跳出「儲存影像」選單 | `-webkit-touch-callout: none` |
| 滑動翻頁時會反白選取到文字 | `user-select: none`（只在圖片區與按鈕） |
| 手勢跟捲動打架 | 圖片區 `touch-action: none`；文字區 `touch-action: pan-y` |
| 螢幕邊緣左右滑會觸發瀏覽器「上一頁」 | 手勢偵測區**避開左右各 20 px** |
| 瀏海與 Home 指示器擋住介面 | `viewport-fit=cover` + `env(safe-area-inset-*)` |
| 雙擊會放大 | `touch-action: manipulation` |
| **iPhone Safari 不支援元素全螢幕 API** | **沒有解。** 唯一去掉瀏覽器介面的方法是**「加入主畫面」的 PWA standalone 模式**。iPad Safari 有支援 `requestFullscreen`，iPhone 沒有 |
| 說到一半螢幕變暗 | **Screen Wake Lock API**（iOS 16.4+ 支援），需要使用者手勢觸發才能取得 |

### viewport meta

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

**不要依賴 `user-scalable=no`** — iOS Safari 會忽略它。要防雙擊放大請用 `touch-action`。

因為這是 iPhone 上唯一的全螢幕方案，值得做一個引導：

## 開放問題

- **「隨機一篇」按鈕** — 孩子說「隨便」的時候很好用。成本很低，列為 MVP 之後的小功能。
- **翻頁動畫要不要做橫向滑入** — 比淡入淡出更符合「投影片」的直覺，但在低階平板上可能掉幀。先做淡入淡出，實測後再說。
- **選單要不要有「最近說過」區塊** — 同一篇常常要連說好幾天。有 localStorage 資料就做得到，列為第二階段。
